# 视觉风格调整

把「改样式」从**目测微调**变成**先定规范、再量、迭代到 0**。

这套方法是在漫画风（`studio`）上走完一遍得出来的：从 66 处违规到 0，气泡 52px → 48px。核心不是任何一条 CSS，而是**规范可量 + 审计脚本 + 只信实测**。

---

## 一、用户的视觉偏好（当成硬规则，不要重新征求意见）

这些是反复确认过的，不是猜测。新风格默认按这些来。

### 1. 有背景的文字，高度必须由字号推出来

这是最核心的一条，用户自己提的：

```
H = lineBox + 2·padY + 2·borderWidth
```

不许手填高度。选中态药丸、气泡、按钮、chip 全部走这个公式。
漫画风的落点：`padY ∈ {4, 6, 8, 10}` → `H ∈ {28, 36, 40, 44}`；单行气泡 `24 + 10·2 + 2·2 = 48`。

用户会直接看出来：「左栏选中的背景高度太小了，对话区我的气泡背景又有些大」。

### 2. 每个风格只有**一种**线宽

漫画风是 `2px`，纯 `#000000`。合法值只有「那一种」和 `0`。
- 没有 hairline。见到 `1px` 就是错的，要么升到风格线宽，要么删掉。
- **两条边框挨在一起 = 太粗**。用户明确反馈过两次。一条边归一个元素，另一个设 `0`——不是两条都调细。
  - 踩过的：`.session-sidebar` 有 `border-right`，`.resize-handle` 又是实心的 → 两条黑线夹一条白缝。留下 handle 那条，它**就是**那条线。

### 3. 字号、字重、圆角都是**闭集**

漫画风：字号 `{11, 14, 15, 16, 20}`、字重 `{500, 600, 700, 800}`、圆角 `{0, 2, 4, 6, 8}`。

- **把字重当旋钮用是明确的错**。`450`、`640` 这种「两档之间」的值抓到就归档。
- 字号写成 token（`--st-t-*`），不写字面量，改规范时是一处改动。

**圆角这一条被改了两次，值得单独记：**

```
R = clamp(2, floor(H/8) 取偶, 8)   硬上限 R ≤ H/6
```

- **让圆角的步长等于线宽**（漫画风 = 2px）。整个风格只有一个尺寸量，圆角阶梯就取它——一套算术而不是两套。
- 12/20 → 4/6/8/12 → 2/4/6/8，降了两次。用户两次的说法是「圆角太大了，小点」和「中栏里圆角还是有点大」。
- **第二次降档的原因不是某个元素太圆，而是最大的那一档在同一栏里出现了三次**：输入框壳、artifact 卡、错误块全坐在 12px 上，中间一竖排三个大软方块。
  → **单看一个元素判断不了圆角。要看同一档位在一栏里同时出现几次。** 默认往小走。

### 4. 阴影：要么没有，要么是 0 模糊的实心偏移

漫画风只有 `0 3px 0 0 <ink>`，**只给能按的东西**。气泡不能按，所以是平的。
环境柔光阴影（`0 14px 34px rgba(...)`）跟这类风格不兼容，一律清掉。

### 5. 图标要按**这个**风格的性格重做

不要把上一个风格的特征顺手带过来。用户为此专门骂过一次：「你不要因为我的插画风有线框，你也加线框」。

- 漫画风：填**字形自身的闭合轮廓**，不是在黑字形后面垫一个色块。（这条做反过一次，用户回「图标不对」。容器只在参考图里出现两次。）
- 牛皮纸：全部面性（实心）。
- 像素风：真的点阵图标集（`pixelarticons`），不是把线性图标缩小。
- 两个咽喉点：`StateIcon`（~65 个语义槽）和 `uiIcons.tsx`（47 个 chrome 名）。`agent-preview/*.tsx` 里**没有**直接 import lucide，所以换图标只需要动这两处。
- 按**槽位**建映射表（65 个），不要按选项（282 个）。先例：`codiconSlots.ts`。

### 6. 字体

- 一个风格说衬线，就是 **中英日都衬线**。字体栈是逐字符解析的：先拉丁衬线，再跟 CJK 衬线。
- **不要假粗**。单字重的字体（如 Ark Pixel）配 `font-synthesis: none`，并把 `--weight-*` 全部压成该字重。用户截图指过：「你不要加粗」。
- `-webkit-font-smoothing: none` 会把 CJK 搞粗，别用。

### 7. 编辑器家具不跟着换皮

hover 出现的编辑/删除浮层，**所有风格都用原生风的样子**。用户原话：「你不用每个风格里都不一样，这个浮层你就都统一原生风里的风格就行」。
风格只作用于 `.preview-frame` 内的内容，不作用于工具条、rail、region label。

### 8. 一整栏就是一种质感

用户为「中栏顶部和中间对话区背景不一样」连提了五次。做背景/纹理时，检查**整列**是不是一张连续的面，别在面板头和内容体之间留缝。

### 9. 并排的两个东西必须一样大

「左右不一样大，都和右边那么大」。同一行里的兄弟卡片要量到同宽同高同 y（实测过 `96x97 @y605` 两边一致才算过）。

### 10. 语义是**叠加**，不是互斥

思考中的图标、文字轮播、计时，三个同时勾选就要三个同时生效 = `icon + 文字切换 + xx秒`。
实现上：它们不能读写同一个字段。文字轮播原来挂在 `theme.motion.reasoning` 上（图标也用这个字段），所以互相顶掉了——加了一个独立的 `reasoning.textCycle` 才解决。
**碰到「选了 A 就丢了 B」，先看是不是共用了一个字段。**

### 11. 数字要活的、人话的

- 从 1s 开始真的往上跳，`setInterval` 1000ms，不是结束时测一次。
- 文案 `已思考3秒` —— 中间**不加空格**，不加括号。用户驳回过「已思考（用时 3 秒）太繁琐了」。
- 超过 60s 换成 `x分x秒`，不要让秒数一直涨。
- 状态还是 `thinking`，只是文案变了。「底层逻辑还是在思考中，没有思考完成」。

### 12. 点击要有真交互

上传就真的弹文件选择，搜索图标就真的出浮层。不要做成装饰。

## 二、方法：定规范 → 写审计 → 迭代到 0

**不要目测微调。** 目测微调的结果是用户一轮轮截图指问题，而你一轮轮猜。

### 第 1 步：写规范，每条都可量

落到 `docs/<STYLE>_SPEC.md`。必须包含一节**可量的验收清单**（漫画风是 §12）：不是「圆角要小」，而是「圆角 ∈ {0,2,4,6,8}」。

判据：这条能不能写进一个 `if` 里？不能就是还没定完。

### 第 2 步：写审计脚本，输出违规**条数**

用项目自带的 CDP：`scripts/lib/cdp.mjs`（`launchChrome` / `connectPage` / `evaluate`）。
模板见本目录 `audit-template.mjs`。它做的事：起 headless Chrome → 点到目标风格 → 遍历 `.preview-frame` 下所有可见元素 → 比对闭集 → 返回 `{ failCount, fails[] }`。

注意 `evaluate(page, body)` 是包在 IIFE 里的，body 需要 `return`。

### 第 3 步：按**族**修，每修一族就重跑

66 → 33 → 11 → 1 → 0。每一步都是实测数字，不是感觉。

- 一开始逐个选择器点名修（66→33），然后发现**剩下的不是一个名单，而是「所有还没被风格分支覆盖到的东西」**——没有自己 class 的元素在继承全局默认值（13px / 450）。
- 这时候正确解法是**把标尺放到 frame 和裸元素上，让继承去覆盖**（33→11），而不是继续加选择器。
- 最后剩下的才是真正自己声明了越界值的，必须点名（11→0）。

**先分清你面对的是「一个名单」还是「一片没覆盖的地」，解法完全不同。**

### 第 3.5 步：审计必须同时校验「是什么值」和「落在什么上」

**只校验值的形状会漏掉整整一类缺陷。** `0 3px 0 0` 是这个风格唯一合法的投影，所以形状检查放它过去了——而它当时正落在工具卡、产物卡和输入框壳上，三个都按不了。审计报 0 违规，用户报「这根线是什么」。

所以每条规则都要问两遍：这个值合法吗？**它该出现在这个元素上吗？**

### 第 4 步：把结果锁进 CI

浏览器审计要 Chrome，跑不进 CI。补一个静态守卫读 `app.css`，断言风格分支里没写过越界字面量。
先例：`src/styles/studioScale.test.ts`。两者互补——静态守卫抓「写下了非法值」，浏览器审计抓「合法值落错元素」。

静态守卫当场抓到了浏览器审计看不见的一条（元素不在默认视图里）。两个都要。

## 三、踩过的坑（别再踩）

### CSS

- **通用规则可能比风格分支更 specific。**
  `.preview-frame .message-item[data-role="user"] .msg-surface` 是 (0,4,0)；
  `.preview-frame[data-style-preset="studio"] .msg-surface` 只有 (0,3,0) —— **通用的赢**。
  样式表里写着 10px，实测 12px，就是这个原因。风格分支要**按被覆盖规则的同样形状**重写。
- **`var()` 解析失败会静默回落到初始值。** `font-weight: var(--weight-body)` 变量没定义 → 算出 `400`。
  **看到一个解释不了的「默认值」，先怀疑变量没定义**，而不是怀疑特异性。
- **`clip-path` 会裁掉 `box-shadow`**（改用 `filter: drop-shadow()`）**也会裁掉溢出的子元素**（浮层宿主改用裁过的伪元素条）。
- `background-position` 用四值语法 `right 5px top 5px`，不要 `calc(100% - 5px)`。
- 本地化的 CSS `content` 用 `:lang()`。
- **不要新增一份平行的规则副本。** 加进已有的那个规则组里。（曾经把 `grid-column: 1 / -1`（管加宽）和 `aspect-ratio: auto; padding: 6px`（管形状）当成一件事一起删了。）

### 定位问题

- **别从源码推断，量运行中的页面。** 中栏质感那个问题连错四次诊断，全是静态读代码读出来的。
- **`CSS.getMatchedStylesForNode` 直接点名是哪条规则在画。** 这是权威答案，第一次就该用它。
- **grep 正则 `[^\n{}]*` 看不见跨行的选择器列表。** 那条画中栏的规则就是这样藏了四轮：
  ```css
  .chat-frame, .composer-frame, .utility-card, .debug-dock { background: var(--surface-panel) }
  ```
- **`getPropertyValue('background')` 对 `background: var(...)` 简写返回 `""`**。读 `rule.style.cssText`。
- **先确认真实 DOM 结构。** 侧栏那行是 `.session-item-shell[data-active]`，里面有 `<span class="session-item-bg">`（真正可见的药丸）和 `<button class="session-item">`。之前所有瞄准 `.session-item` 的规则都打空了。
- **投影既不是元素，也不参与命中测试。** 一根由 `box-shadow` 画出来的线，`querySelectorAll('*')` 扫不到，伪元素也扫不到，`elementFromPoint` 返回的是它背后的东西。
  → **用像素扫描定位**：`Page.captureScreenshot` 截图，逐行统计「连续暗像素」，找出长暗带的确切 y。拿到 y 再回 CSS 里找谁的盒子在那结束。这是找了三轮才用上的方法，应该第一轮就用。
- **零模糊偏移投影有三种读法，判断靠偏移的轴数：**
  | 形状 | 读作 | 通常 |
  |---|---|---|
  | 双轴偏移 `6px 6px 0 0` | 背后叠了一张卡 | 有意的 |
  | 单轴偏移 `0 3px 0 0` | **一条边** | 在宽面板下 = 一根横贯的线 |
  | 零偏移带扩散 `0 0 0 1px` | ring | 等同边框，无害 |
  另外：偏移投影需要**前面有一个实心的面**挡着它。背景透明+边框 0 的按钮配 `0 3px 0 0`，画出来的只有一条悬空的黑弧。
- **绝对定位 + `min-height` 会向下生长。** `.session-item-bg` 有 `inset: 2px`（在 36px 行里本该 32px 高），我又给它 `min-height: 36px`，它就从顶部 inset 往下长了 4px —— 药丸比按钮低 2px、超出 2px。文字在**按钮**里是居中的，在**药丸**里上 6 下 10。
  → 量「文字相对**真正画出来的那个形状**」的上下间距，不是相对它的父元素。
- **Chrome 对 `border-width` 的小数值向下取整。** `border-width: 1.5px` 的 computed 值是 `1px`——**DPR 2 下也一样**,2x 截图里实测只画 2 个设备像素而不是 3 个。`outline-width` 同样取整。只有 `box-shadow` 的 spread 保留小数,但投影不占布局空间,会把高度公式一起带走。
  → 用户说「改成 1.5px」时,**先用一个隔离元素测一下这个值到底存不存在**,再决定。1px 就是 1.5px 实际渲染出来的样子。
- **改线宽会把高度公式一起改掉。** `H = lineBox + 2·padY + 2·border`,线宽降 1px 意味着每个高度掉 2px。**高度是和用户约定过的东西,内边距才是吸收线宽变化的那一项**——padY 每档加 1px,36 和 48 就一点没动。不要让用户认过的高度悄悄变。
- **CSS 模块里写死的圆角跟任何风格都无关。** 图片加载模块给图和每层裁剪容器都写了 `clamp(28px, 7%, 64px)`，在卡片圆角 8px 的风格里读作完全不同的形状。用 `border-radius: inherit` 沿 卡片→按钮→reveal→裁剪层→img 传下去，每个风格自己的圆角自动生效。装饰性动画色块（999px 的 blob）要排除在外。

### 别的

- **风格 id 和中文名可能对不上。** 「插画风」是 `studio`，不是 `illustrated`。改之前先查 `PresetStyleId`。
- `applyTheme` 写在 `document.documentElement` 上。**只设 `data-style-preset` 不会应用主题**，两件事。
- **资产许可分级**：CC0-1.0（无义务）> MIT（保留声明）> CC-BY-4.0（署名，会跟着导出走）> OFL-1.1（字体必须带上许可文本）。
- **导出平价**：`scaffoldStyles.ts` 用 `?raw` 原样内联 `app.css`；二进制进 `SCAFFOLD_PUBLIC_ASSETS`；npm 依赖进 `createScaffoldPackageJson`；`exportFacts.ts` 的 `EXPORT_FILE_COUNT` 要跟着动。
- **用户说不对的时候，回到他的参考图重新推导。** 牛皮纸第一版做成了白底+黑细线+扁平，因为我沿用了上一个风格的做法；参考图其实是牛皮棕+撕纸边+纹理+阴影。重做。
- 用户说「我说的是视觉样式，不是内容」——改皮的时候不要顺手改文案和结构。
- **不要扩大用户圈定的范围。** 用户红框标了 4 个图标说「小了」，我把整个风格的图标尺寸统一成两档，被要求还原。「一个界面里五种图标尺寸太多」是对的，也仍然不是被要求的事——它应该作为一个单独的提议，而不是搭车改掉。
- **有例外就按名字点名，并且用测试锁住名单。** 用户指定的图标 tile 是 `border-radius: 20px` + `border: 3px`，都在闭集之外。正确处理不是放宽闭集，也不是把用户的值改掉，而是：认定「图标 tile = 容器和字形是一整块画，圆角听画的」，在规范里写下这条例外，在守卫里按选择器豁免，再加一条测试断言**豁免名单就是这一个**。一个选择器宽的是例外，通配符是规则上的洞。
- **「这根线是什么」往往不是样式问题，是某个选项被默默打开了。** 用户指着一根线问「能去掉吗」，先查它是不是某个 preset 选项渲染出来的，而不是先去调它的 CSS。
  - 真实案例：工具调用进度条（3px、999px 圆角、无描边）。它所在的 section 只有**一张卡**，而 `isExclusiveSection` 需要两个成员才能测出互斥，所以被判成「可叠加」→ 整节取走 → **六个风格全都默认带上了它**。没人选过它。
  - **规律：单卡 section 会变成所有风格的默认值。** 加新选项时留意这一点。
  - 解法是 `STYLE_KIT_OMISSIONS`（`STYLE_KIT_OVERRIDES` 的对称表，只能加不能减，所以补了一个）。过滤要放在**选项进入 requested 之前**，否则从互斥集里去掉一个成员会让整节落空，而不是让下一个顶上。

## 四、落地顺序

1. 读用户的参考图/截图，**从它推导**，不要从现有实现推导。用户原话：「不要受现在呈现的局限，毕竟现在呈现的好多都有问题」。
2. 写规范文档，含可量的验收清单。
3. 建 token 层：间距、高度、字号/行高、圆角、字重、线宽、阴影各一组 `--<x>-*`。**高度由公式推，不手填。**
4. 把 token 映射到项目既有的 token 上（`--fn-r-*`、`--radius-*`、`--shadow-*`、`--surface-*`、`--text-*`、`--accent*`、`--font-*`），这样所有组件自动跟随。
5. 写审计脚本，跑，拿到基线条数。
6. 按族修，每族重跑。判断是「名单」还是「一片没覆盖的地」。
7. 到 0。
8. 补静态守卫测试锁住。
9. `npx tsc --noEmit` + `npx vitest run`，并确认失败项是不是**之前就有的**（用 `git stash` 验一下，别背别人的锅）。
