# 字号规范：三档，一套，六个风格

这份文档回答两个问题：**一段文字的字号该从哪里来**，以及**现在实际是多少**。

「现状」一节的数字全部是实测值 —— 在 1680×1200、缩放 100% 下逐个风格切换，读每个角色元素计算后的 `font-size`，不是从代码里推的。复现方法见 §5。

---

## 一、刻度

### 1.1 三档，就是全部

```
16px  标题     --preview-title-size
14px  正文     --preview-copy-size
12px  附注     --preview-meta-size
```

**六个风格共用这三档，没有第四档。** 新的文字元素属于标题、正文还是附注？取对应的 token。不要按「看着差不多」挑数字，也不要因为某个风格「应该大一点」就加一档 —— 那是字体和字重的事，不是字号的事。

### 1.2 跨风格统一的角色 token

有一类文字所有风格都必须一样，因为它表达的是产品的语义层级而不是风格的性格。这类在基础样式里定义，风格分支不覆盖：

| token | 值 | 管什么 |
| --- | --- | --- |
| `--reasoning-type-size` | `14px` | 思考块的标题和正文（两半必须同字号，见 §3.3） |

### 1.3 唯一的例外：流体刻度

**复古风**（`retro`）的三个 token 是 `clamp(min, X cqi, max)`，跟画布宽度走：

```css
--retro-title: clamp(14px, 2.825cqi, 16px);
--retro-body:  clamp(10px, 1.766cqi, 14px);
--retro-small: clamp(8px,  1.272cqi, 12px);
```

**上限就是上面那三档**，所以桌面下它和其他五个一模一样，只有画布被压窄时才按比例缩小。

流体必须整套流体：正文 `cqi`、标题写死 px 的话，窗口一变两者比例就漂了。

**这套 token 现在有三份，一份对一个容器。** `cqi` 算的是「用到它的那个元素最近的容器」，所以系数必须按那个容器的内容宽度来定，否则上限永远够不到：

| 作用域 | 容器 | 内容宽 | 系数（标题/正文/附注） |
| --- | --- | --- | --- |
| 画布整体 | `preview-frame` | 1104px | 2.825 / 1.766 / 1.272 |
| 中栏＋右栏 | `retro-center`（`.preview-panels`） | 872.59px | 3.067 / 1.917 / 1.381 |
| 左栏 | `retro-sidebar` | 180.65px | 12.536 / 8.369 / 6.267 |

三份的上限都是 16/14/12。两次修正（左栏 ×1.2699、中栏 ×1.0857）都是同一个原因：系数按设计稿的框宽写的，解析的却是某个更窄的容器内容盒。

## 三、这 12 种是怎么变成 3 种的

统一不是「把每个风格的数字改一遍」，而是堵掉四个**逃逸口**。记下来，因为下一个逃逸口会长得一样。

### 3.1 基础规则里写死的 px

角色标签 13、打开方式 16、卡类型 14、错误正文与中断行 15、错误小字 11、权限按钮 13 —— 全部写在 `.preview-frame` 这一层。所有风格照抄，所以「六个风格一致」，但没人决定过这些数字，它们只是没接 token。

> **规则**：除 §1.1/§1.2 的 token 定义处，`app.css` 里不应再出现 `font-size: <数字>px`。

### 3.2 一个风格带着第二套刻度

漫画风有自己的 `--st-t-display / title / body / row / label = 20/16/15/14/11`。这是它成为唯一 15px 正文、11px 标签的全部原因。

处置：**五个名字留着**（读它们的规则值得保持可读），每个指向共享 token。

> **规则**：风格可以有自己的刻度**名字**，不能有自己的刻度**数值**。

### 3.3 没被定过尺寸的角色，会继承根字号

`.msg-surface` 在用户那一侧没有任何 `font-size`，于是一路继承到画布根的 16px —— 比它旁边的正文大两档。这类漏洞不会出现在 grep 里，只会出现在测量里。

### 3.4 一条过宽的规则压过角色规则

复古像素风的 `:is(p, li, td, span, button, input, textarea)`（权重 0,3,0）压过所有标签角色（0,2,0），于是它的标签拿到了正文尺寸。`span` 和 `button` 就是标签的载体，已从名单里删掉；这条规则的本意是「点阵字体要整数磅位」，而共享刻度本来就是整数。

> **规则**：风格分支里不要按 HTML 元素设字号。角色是 class，不是标签名。

### 3.5 别名把旧值冻住了

第五个逃逸口，2026-09-19 发现，只能靠测量看见。

`var()` 是在**声明它的那个元素上**替换掉的，不是在最终用它的元素上。`--preview-meta-size: var(--retro-small)` 写在画布根上，所以它当场冻住了根上那份 `--retro-small`，往下继承的是**已经替换完的那串 token**。于是给 `.preview-panels` 补一份修正过的 `--retro-small` 之后：

- 直接读 `--retro-small` 的规则（中栏的角色标签等）→ 拿到新值，12px ✓
- 读 `--preview-meta-size` 的规则（右栏那 52 处）→ 还是旧值，11.0994px ✗

同一个元素、同一个容器、两个答案，差别只在规则用了哪个名字。修法是在重新定义刻度的那个块里**把三个别名一起重新声明**，`typeScale.test.ts` 有一条护栏钉住这件事。

> **规则**：把流体刻度重新作用到某个容器时，`--preview-title-size / copy / meta` 三个别名必须在同一个块里跟着重声明。只改输入不改消费者，等于什么都没改。
>
> 注意 `clamp()` 里的 `cqi` **不走**这条 —— 自定义属性里的容器单位是当 token 存着的，到最终使用的元素上才按它的容器解析。所以只有 `var()` 会冻，长度不会。

## 四、为统一付出的代价（记录在案）

三处原本有理由的差异被抹平了。如果将来要把哪一个放回去，这里是它当初的理由：

| 风格 | 原值 | 理由 | 现在 |
| --- | --- | --- | --- |
| 复古风 画布标题 | 25.14px | Figma 稿的比例，大衬线是这个风格最响的特征 | 16 |
| 手绘风 画布标题 | `1.35em`（21.6px） | Caveat 这类手写体在相同点数下**视觉偏小**，放大才能和其他风格等重 | 16（所以它现在看起来会比别人的标题略小） |
| 游戏风 画布标题 | 18px（`--text-xl`） | 衬线大字 | 16 |
| 复古像素风 画布标题 | 15px | 点阵字体的可用磅位 | 16 |

统一之后，风格之间的差别由**字体、字重、行高、颜色、边框**承担，不再由字号承担。

> 已清理的历史遗留：复古风分支里那条给思考块设 13.5px 的规则（早被 `--reasoning-type-size` 盖掉）、基础样式的 `--text-md`（13.5px）不再管工具行标题。

## 五、怎么验证

字号的真相只有一个来源：**计算后的样式**。CSS 里的 `13px` 可能被一条更具体的规则盖掉（本文档里至少有四处就是这么发生的），所以改完必须量。

1. `npm run dev -- --port 5175`
2. 用 CDP 打开 `editor.html`（`scripts/lib/cdp.mjs`；视口 `Emulation.setDeviceMetricsOverride` 设 1680×1200；`evaluate` 的函数体要 `return`）
3. 从右侧风格卡片点「应用」切风格（确认弹窗已经不存在了）
4. 等整条回复铺完（`.artifact-launch-card` 与 `.error-item` 同时出现），否则量到的是半条回复
5. 逐个角色读 `getComputedStyle(el).fontSize`

三个会让你白跑一趟的坑：

- **切风格时画布重新挂载**（450ms 交换动画），期间 `.preview-frame` 为 `null` —— 每次读之前判空，否则探针直接抛错。
- **改完 CSS 要等 Vite 落盘**。本轮有两次测到旧值，都是探针在写盘前就加载了页面；重量一遍就对了。想确认某条规则到底有没有生效，用 `CSS.getMatchedStylesForNode`（DevTools 协议）—— 它会把**输掉的那一侧**也列出来，`getComputedStyle` 只告诉你结果、不告诉你谁赢了。
- **折叠起来的量不到**：工具卡默认收起、思考块落定后收起，里面的文字要先展开才有。

## 六、护栏（已实现）

`src/theme/typeScale.test.ts`，四条断言：

1. **没有第四档** —— 画布相关规则里的固定 px 只能是 12 / 14 / 16（`font-size: 0` 例外：那是图标按钮隐藏文字标签的写法，不是字号）。
2. **风格分支不许自带数值** —— `[data-style-preset="…"]` 里的 `font-size` 只能是 token、`clamp()`、`em`、`inherit` 或 0。风格可以有自己的刻度**名字**（漫画风的 `--st-t-*` 留着，读它们的规则更好读），不能有自己的刻度**数值**。
3. **复古风的流体上限必须是这三档** —— 中栏和左栏两套 `--retro-*` 都查，上限分别是 16/14/12。
4. **三档只在一处声明** —— 三个 token 的定义行。

### 例外清单（写在测试里，每条带理由）

| 选择器 | 值 | 为什么 |
| --- | --- | --- |
| `[data-style-preset="workbuddy"]` | 13px / 12px | **不是本刻度管的风格**：它是对外部客户端的还原，数字是量出来的（13px 气泡配 19px 行、12px 文件行），`workbuddyStyle.test.ts` 拿它们和原稿对照。统一到 14 会让那两条断言红 —— 那是正确的结果：刻度管的是读者能选的风格，而它是隐藏的。 |
| `[data-style-preset="workbuddy"] .composer-greeting-text` | 36px | 空画布上的问候大字，是标题而不是类型角色。 |
| `[data-style-preset="pixel"]` | 12px | 像素风的**根**字号，不是角色：点阵字体只有一个可用磅位，那个分支里所有长度都是它的倍数。风格可以定自己的根，不能用字面量给角色定尺寸。 |

> 「例外必须写下来」本身是规则的一部分：写下来的例外，是有人读过的例外。

### 这一轮顺手补的

第一次跑这条护栏时它报出 **28 处** —— 说明「三档」当时只在我测过的那 18 个角色上成立。没测过的地方还带着十种字号：输出面板标签 13、状态胶囊 13、产物行 kind/status 11、`pre` 13、代码标题 15、媒体信息 17/18/13/11、媒体时间 10.5、揭示标签 12.5、来源切换 12.5、原生风的上下文胶囊 13。全部按角色接了 token。

**这件事值得记住**：护栏的价值不是守住已经修好的部分，而是**告诉你哪里还没修**。

## 七、表头行高：同一个类型的错误

字号统一之后，读者仍然看出「复古风的标题和两个图标比原生风高」。**六个风格的表头当时都在各自的行里居中得完全正确** —— 行盒、标题、图标的中线在每个风格内部都是同一个值，`getBoundingClientRect` 报的是「居中」，而眼睛报的是「偏高」。眼睛是对的。

原因是**行本身高度不同**：原生风 60px、复古风 48px、漫画风 56px、手绘风由内容撑开。于是同一个标题在不同皮肤下落在画布的不同高度上。实测内容中心距画布顶：复古风 24px，原生风 30px。

处置：**行高只有一处声明**（`--preview-header-height: 60px`），风格分支不得再设 `min-height` / `height` / 块向 padding。风格仍然可以设**横向**内缩 —— 那是标题到栏边的距离，读起来确实是风格自己的。

现在六个风格：左栏品牌行和中栏表头都是 60px，且两行的中线、名字、图标、标题全部落在同一条线上（复古像素风的左栏因为有 2px 面板描边，把双倍描边从块向 padding 里扣回来才对齐 —— **块向 padding 的不对称只会把中心移动它的一半**，这一点值得记住）。

> **教训**：「在自己的盒子里居中」和「在画布上对齐」是两件事。前者用 `getBoundingClientRect` 能验，后者必须跨风格比同一个角色的绝对位置 —— 单个风格测一百遍也发现不了。

护栏见 `src/theme/typeScale.test.ts` 的 `canvas header row` 两条断言。
